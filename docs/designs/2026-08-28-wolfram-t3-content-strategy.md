## 0. The question, made precise

The ask: for **T3 content**, can the Wolfram **local/cloud MCP** connection be
used; can the **Wolfram Demonstrations** corpus, via MCP, become a source of
customised content; and what is the right strategy given Wolfram is a quality
standard.

**"T3" disambiguated (repo audit).** Four tier vocabularies exist; two matter
here and both put Wolfram at tier 3 by convention:
- `src/verification/tiered-orchestrator.ts` — answer-verification **Tier 3 =
  Wolfram|Alpha arbitration** (built-in slot; `registerVerifier()` reserves
  tiers ≥4 for extensions).
- `src/content/resolver.ts:297` — the content resolver's own `tier3()` =
  "Wolfram MCP verification for high-stakes", calling the same
  `verifyProblemWithWolfram`.

So "T3 content" = **content whose mathematical truth is anchored by a CAS**,
with Wolfram as the reference standard. That is this strategy's scope.

## 2. Premises (final gate confirms)

1. **Rendered widgets stay dependency-free (hard rule); budgeted synchronous
   verification calls are the existing pattern (already live in the cascade).**
   The line is drawn precisely: no student page ever *renders* through
   Wolfram (embeds, iframes, live plots — rejected); the cascade's occasional
   capped verification call inside a grade request is today's architecture and
   stays.
2. **The standard is already encoded — the switch is off, and the switch has a
   license question in front of it.** Activation is ~15 operator minutes of
   code-free work, but the ToS read comes FIRST (Premise 5).
3. **SymPy carries the bulk; Wolfram arbitrates the residue.** The repo's own
   documented architecture ("RAG → SymPy → Wolfram") is the right one and was
   simply never built. A free, local, license-clean CAS should do the
   high-volume authoring-time and CI-time checking; Wolfram's quota and
   licensing exposure shrink to the cases SymPy can't parse or disagrees on.
   This plan builds the missing tier instead of routing around it.
4. **Demonstrations are a design standard, not a content library — and
   curation is parked, not scheduled.** NC + dead CDF close the import path.
   The idea-level standard is real but is backlog material (TODOS), not a
   committed deliverable with metrics: its legal gate is unlikely to clear
   soon and it does not serve the pilot.
5. **No licensing fact in this plan is settled, so nothing license-bearing
   activates before the terms are read.** Commercial API $/call, LLM Kit
   price, Engine production license, Show Steps redistribution, and whether
   "pre-revenue pilot" even qualifies as non-commercial — all unconfirmed.
   The operator's terms-pull GATES production activation, not just future
   monetized use.
6. **MCP is an authoring instrument, and W-B is BLOCKED (not merely
   "unlocked") by connector authorization.** A session that finds the Wolfram
   MCP unauthenticated must stop and report — never proceed, never
   approximate a CAS result.

## 3. The strategy — two moves, one posture, one parking lot

### Move A — Activate the standard, license-first (operator, ordered, ~1 hour)
1. **A1 (gates A3):** pull the terms: WA API commercial pricing + whether the
   pilot qualifies for the free tier's non-commercial clause; LLM Kit price;
   Engine production-license terms; Show Steps redistribution terms. Record
   verbatim in `docs/ops/content-verification-runbook.md`. (All four pages are
   proxy-blocked from agent sessions — this is genuinely operator work.)
2. **A2:** authorize the **Wolfram MCP connector** for Claude sessions
   (claude.ai Settings → Connectors → Wolfram). Unlocks the W-B posture.
3. **A3 (only after A1 clears it):** obtain the AppID and set
   `WOLFRAM_APP_ID` on the Render service. Tier 3 verification, gate-ledger
   `wolfram_verified` evidence, `wolfram-verify-job`, and the pilot's
   `wolframCheck` leg go live — zero new code, 50-calls/day cap already
   enforced.

### Move B — Build the missing SymPy tier + provenance honesty (code, small)
1. **B1 — the SymPy `AnswerVerifier`** (the CEO-review critical): a Tier-4
   verifier registered via `registerVerifier()` (its first real caller),
   implementing the contract in `src/verification/verifiers/types.ts` and
   passing the existing verifier contract test. Execution: local `sympy`
   via a sandboxed Python subprocess (no network, no license), covering
   Solve/simplify/equality-check for closed-form GATE material; refuses
   honestly (D8 style) on anything it can't parse rather than guessing.
   Placement decision (cascade order semantics: cheap-local SymPy should run
   BEFORE the metered Wolfram tier even though its registry number is ≥4) is
   an eng-review question — surface, don't assume. Fixes the repo-wide doc
   drift EITHER way: docs match code when this lands.
2. **B2 — provenance convention:** `verification_method` values gain the
   validated convention `…+sympy` / `…+wolfram` with `verified_at`;
   `check-practice-items.ts` enforces the vocabulary. Backfill only what a
   session actually re-verifies — the 123 LA items' release-note claim is
   never retro-stamped.
3. **B3 — `/verify-sweep` honesty:** repoint the skill doc at the real
   `wolfram-verify-job` (+ its env caps), or implement the missing operation
   file on top of it; delete the phantom-table references.
4. **B4 — evidence surfacing check:** verify the review queue renders the
   `mathematics` gate's CAS evidence string prominently (data exists; confirm
   the UI shows it).

### Posture W — Wolfram MCP in authoring sessions (no build, blocked on A2)
In MCP-authorized sessions, agents use `WolframLanguageEvaluator` **ad hoc**:
CAS-check answer keys that SymPy refused or that arbitration needs; prototype
plots to sanity-check a gif-scene or widget spec before committing it;
sanity-check parametrized problem families. Rules: unauthenticated connector →
stop and report; results recorded per B2's convention; no dedicated
WL→widget translation adapter is built until repeated real sessions
demonstrate the need (the adapter idea is recorded in TODOS with its trigger:
"3+ authoring sessions each hand-translating WL output").

### Parking lot (TODOS.md, not this plan's scope or metrics)
- **Demonstrations-as-visual-standard curation** (`concept → demo idea →
  widget spec` mappings) — parked with its trigger: a real legal read on
  independent re-implementation + the pilot complete. MIT preview snapshots
  usable as authoring reference if/when picked up.
- **WL→safe-evaluator translation adapter** — trigger above.
- **Show Steps content in worked examples** — trigger: A1's terms answer.
- **Wolfram Engine batch asset generation** — trigger: a demonstrated need
  `gifenc` can't meet AND a production license.

### Rejected (explicit)
- **R1 — student-facing Wolfram Cloud embeds/renders**: uptime dependency
  with a documented outage history; violates the dependency-free widget rule;
  free-tier 60-day expiry rots pages silently.
- **R2 — importing/embedding Demonstrations content**: CC BY-NC-SA; CDF dead.
- **R3 — MCP inside the generation pipeline**: duplicates the cascade's
  post-hoc verification, adds latency and a live dependency to every
  generation call.

## 5. Failure modes

| Path | Failure | Handling |
|---|---|---|
| A1 terms say free tier doesn't cover the pilot | A3 waits for a paid key decision; SymPy (B1) carries verification meanwhile — the plan degrades to license-clean | by construction |
| Tier 3 live, key invalid/quota hit | cascade falls back (confidence-penalized LLM verdict), never blocks | existing, tested |
| SymPy can't parse an expression | honest refusal naming the head; item routes to Wolfram arbitration or hand-check — never guessed | B1 spec |
| SymPy and Wolfram disagree | item flagged to the review queue with both values; writer guard already refuses silent overwrites | existing D5 + B2 |
| MCP session finds connector unauthenticated | stop and report (Premise 6) — never approximate | posture rule |
| Demonstrations legal read negative (if ever picked up) | parked item stays parked; independent-code specs unaffected | parking-lot trigger |

## 6. Success metrics
1. A3: production logs show Tier 3 active; first `wolfram_verified` evidence
   rows in the gate ledger.
2. B1: SymPy verifier registered + contract test green; cascade logs show
   SymPy handling ≥ the majority of authoring-time checks with Wolfram calls
   reserved for arbitration (observable in `verification_log.tier_used`).
3. B2: `ci:practice-items` enforces the provenance vocabulary; zero items
   claim CAS verification without a structured record.
4. Pilot service: operator minutes-per-verified-item with CAS evidence
   attached vs without (the review queue's meter already measures it).
