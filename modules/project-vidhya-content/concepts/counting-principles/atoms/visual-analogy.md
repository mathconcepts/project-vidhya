# Permutations vs Combinations: A Concrete Analogy

Think of **permutations** like a **race medal podium**. You have 5 runners, and you're awarding gold, silver, and bronze. The runner in position 1 (gold) matters — it's not the same as position 2 (silver). You're counting **ordered arrangements**: Alice-gold, Bob-silver, Carol-bronze is different from Bob-gold, Alice-silver, Carol-bronze.

Now think of **combinations** like **choosing fruit for a smoothie**. You have 5 fruits and want to pick 3. Picking apple-banana-orange for the smoothie is the same as banana-orange-apple — the order doesn't affect the final smoothie. You're counting **unordered selections**.

**The key difference:** Permutation = position/order matters. Combination = just which items are chosen.

**Exam insight:** If a problem says "arrange," "order," "line up" → permutation. If it says "select," "choose," "committee" → combination.
