## 0. What this plan responds to

Adverse feedback named three things: **content readiness**, **content
preparation**, and **content handling structure**. The user commissioned an
independent market study (177-file corpus: pain-point research, a 116-topic
atomic inventory with a validated prerequisite graph, a research-first
content-generation framework with schemas and policies, 10+106 remediation
workflow contracts, a constraint/observability framework, a manim animation
skill, and official GATE XE 2021–2023 paper analysis). The job: compare it
against Vidhya, adopt what is better, and produce a rock-solid improvement
strategy. GATE Engineering Mathematics is the pilot; IIT JEE mathematics
follows.

**Prior art (not re-litigated):** the 2026-08-25 intent-driven restructure
answered the *first* round of this feedback. Verified in-repo this session:
its T1–T5 are **shipped in code** — the 203-atom demand catalogue
(`data/curriculum/gate-em/`), intent profiles, CI catalogue gate
(`ci:intent-catalogue`), problem-statement block
(`ProblemStatementBlock.tsx`), intent-aware blueprints
(`intent-tables.gen`), and the full PYQ→concept mapping (241/241). **But the
student-visible piece is dark**: the problem-statement block is gated on
`VIDHYA_INTENT_LANES`, which defaults off and is not set on the demo deploy.
The demo still opens every concept the old way — the original feedback
source is retired in code and live in production. That inversion sets this
plan's P0.

Open tasks inherited from that plan: lane chips (T4b), inventory floor +
generation (T6), ErrorTag extension + trap drills (T7), cross-paper packs
(T8). This plan absorbs T6/T7 and re-specs them; T4b/T8 unchanged.

## 3. Premises (the final gate confirms these)

1. **Interpretation of the feedback (marked: unverified).** This plan reads
   "content readiness / preparation / handling structure" as depth+exam-craft
   / provenance+governance / anatomy. The plainer reading — "there isn't
   enough content and it's thin" — is served by the core plan alone (P0–P3);
   the governance and anatomy expansions assume the richer reading. If the
   feedback source can give one clarifying sentence, it re-weights the
   expansions; the core plan is right under either reading.
2. **The market study is a spec library, not a content library.** Its 114
   packages are generation contracts stamped `candidate_pending_review`; the
   adoptable value is governance, anatomy, and the diagnosis/remediation
   protocol — with its constants held as hypotheses (§2 preamble).
3. **Vidhya's engine + measurement stack is the keeper.** Everything adopted
   lands as data, policy, or thin modules on existing seams.
4. **The concept graph remains the single mastery spine.** The study's
   116-topic graph is a validation/enrichment source, never a second runtime
   taxonomy (reaffirms 08-25 D2/D5).
5. **Verification labor, not generation, is the inventory bottleneck.** The
   123 hand-verified LA items were a significant one-operator effort. Fill
   targets and timelines are set from measured verification throughput, with
   a sampled-verification protocol whose spot-check rate derives from the
   first module's measured error rate — the 08-25 plan's own formula,
   restored. The catalogue's 8,725 total is a planning constant, never a
   commitment.
6. **Expansion is student-gated.** Phases beyond P3 require a real cohort
   producing attempts (activation gate in §7). Without students, remediation
   machines, calibration metrics, and delta-lift cells are instruments in a
   lab with no specimens.
7. **GATE pilot → JEE follows, and the contract must be JEE-Advanced-proof
   on paper first.** W1.1's schema is designed against JEE Advanced's
   partial-marking matrices *before* implementation (a paper exercise). The
   contract carries per-question-type `marking_strategy` identifiers plus
   parameters; the scorer resolves strategies from a registry. Pure
   parameters cover GATE + JEE Main; a genuinely new scheme is a new
   registered strategy, never a fork of the scorer.

## 4. The strategy — three workstreams matching the three feedback words

### W1. Content PREPARATION → the Governance Contract

- **W1.1 Versioned Assessment Contract.** Migration + loader + seed row from
  the corpus's verified GATE 2026 facts (MCQ −1/3|−2/3, MSQ no-partial
  no-negative, NAT no-negative + tolerance, EM = 13 marks, XE-A = 15).
  Schema shape per Premise 7: `(exam, paper, year)` key, per-question-type
  `marking_strategy` id + params JSONB, `official_source_url`, `verified_at`.
  `GateDeterministicScorer` becomes the `gate_2026` strategy reading params
  from the contract; attempts stamp `contract_version`. JEE Main = a second
  row, zero code; JEE Advanced = one new registered strategy.
- **W1.2 Evidence labels.** `evidence_level` on PYQ pattern claims and atom
  exam-relevance statements; D/P/S codes imported for the 116 topics; CI
  rule: no "high-yield / frequently-asked" copy without `directly_reviewed`
  or a coded corpus. Applies reflexively to this plan's imported constants.
- **W1.3 Quality-gate ledger.** Per generated batch/unit: named gate
  statuses (scope, mathematics, assessment-contract, misconception-coverage,
  provenance) alongside the `canonical` lifecycle; answer keys, marking
  rules, canonical definitions always require operator approval.
- **W1.4 Regression-case bank.** DEFERRED until the first real production
  content failure exists to seed it.
- **W1.5 Syllabus freshness.** An annual operator checklist item with the
  official URLs + stored hashes in a doc — not a system.
- **W1.6 Anti-gaming guards in the ledger.** Promote → operator review when:
  immediate lift with flat delayed retention; MCQ up while NAT down; time
  down while errors up. Pure functions over data the ledger already reads.

### W2. Content HANDLING STRUCTURE → the Package Anatomy

- **W2.1 Template families.** 14 families as data
  (`data/curriculum/gate-em/template-families.yml`) codegen'd into
  `template-engine.ts`'s existing StageKind/AtomKind vocabulary +
  `presentation` hints (family sequences are `design_hypothesis`).
- **W2.2 Anchor IDs.** Stable anchor ids on stage instances in the
  blueprint→unit translation (additive metadata; no locked-contract
  mutation). Cheap now; everything delta-shaped later attaches to these.
- **W2.3 Anchored deltas.** DATA-GATED: ships when any stance-variant
  experiment reaches n ≥ 30 (first evidence the finer grain is measurable).
  Then: `misconception_contrast` / `prerequisite_bridge` / `timed_variant`
  deltas attached to anchors; conflict with base → refuse + review.
- **W2.4 Composition manifests.** Same gate as W2.3 (its measurement layer).
- **W2.5 `decision_tree` interactive kind (4th widget).** Method-selection
  trainer (region closed? boundary oriented? → method + reason code).
  Ships with VC theorem selection, distribution choice, PI-template choice,
  rank/consistency. Dependency-free, versioned spec, same safe-evaluator
  pattern.
- **W2.6 Checkpoint-branched lesson flow.** Same gate as W2.3 (branches
  route to deltas).

### W3. Content READINESS → Depth with Exam-Craft

- **W3.1 Mode-readiness dimensions.** Per (concept, mode): gap detection
  from attempt data (correct-MCQ + wrong-NAT). Two added dims (mode,
  fluency), feeding nextBestAction as modifiers. STUDENT-GATED.
- **W3.2 Risk & attempt-discipline training.** Post-mock counterfactual from
  mock-to-marks' leftOnTable ("attempting Q17 cost you 0.67; at your
  accuracy, skipping earns +2 EV") + a 5-item attempt/skip drill using
  break-even p = P/(R+P) from the contract; NAT entry-discipline items.
  The most student-visible, lowest-dependency item in the plan — runs early
  (P2), needs only W1.1.
- **W3.3 Remediation workflow contracts.** Data-driven state machine
  (two-signal trigger → probe → smallest bridge → immediate → FSRS-scheduled
  delayed check → transfer check → exit; escalate after 2 cycles; budgets as
  `design_hypothesis`). Pilots: LA-05 (rank decision tree), VC-11 (W2.5
  widget). STUDENT-GATED.
- **W3.4 Failure taxonomy → ErrorTag extension (absorbs T7).** Union
  extension migration: `method_selection`, `representation`, `mode_msq`,
  `mode_nat_entry`, `time_pressure`, `risk_decision`, `prerequisite`
  (+ existing 6). Distractor generation requires each MCQ distractor to name
  its failure hypothesis.
- **W3.5 Inventory fill (absorbs T6).** Floor gate reads per-atom targets
  report-only (targets = planning constants). **Labor arithmetic governs
  scope**: an anatomy-pilot batch of 50 items runs first through the full
  W1.3 gate path; its measured operator-minutes-per-verified-item and error
  rate set (a) the sampled spot-check rate and (b) the wave-1 target.
  Wave 1 covers the corpus's top-10 leverage atoms (LA-05, PS-03, VC-11,
  CA-21, CA-13, NM-08, NM-09, PS-04, DE-05, CA-18 — ordering is
  `design_hypothesis`), each run carrying mode mix, misconception-linked
  distractors (W3.4), MSQ truth-set verification, NAT tolerance per
  contract. Kill criterion: if 6 weeks of wave 1 produce <300 verified
  items, stop and reassess the protocol before any wave 2.
- **W3.6 Media QA loop.** Post-render frame extraction + legibility/overlap
  check → `media_artifacts.status='failed'` on fail. Applies to the 70
  rendered scenes + future renders.
- **W3.7 Confidence & calibration.** Optional one-tap confidence
  pre-reveal; calibration error as aggregate + ledger protected metric.
  Per-attempt nullable field, no per-student profile. STUDENT-GATED.
- **W3.8 Triage & re-entry session modes.** Visible-deferral triage +
  no-shame re-entry on `SyllabusAwareReadinessEngine`. STUDENT-GATED.

### W-UI. UI contracts for the student-visible surfaces (design-review fold)

Each P0–P2 surface gets its contract HERE, before any component exists — the
standard is `ProblemStatementBlock`'s 25-line header comment, written in
advance. Backend failure modes live in §8; these are the design rulings.

**P0 — DPS block flag-on QA (adds a tone pass).** "QA" means two things:
(a) render QA across LA pages; (b) a register pass reading all ~26 LA
`pain_point` strings in sequence. The block opens every page with "Where
marks die on this topic" — a daily loss prime for the anxious persona the
platform explicitly models. If more than a few openers are fear-framed,
reorder exam-intent-first (the actionable fact before the wound) or soften
the eyebrow. Copy edit, not rebuild; costs nothing at P0.

**W3.2 counterfactual (on the mock results page, never an interstitial):**
- Four-beat copy contract, in order: (1) **earned** — the score, plainly;
  (2) **knewIt** — "you knew enough for N more marks" (competence proof,
  same number as leftOnTable reframed); (3) the gap framed as *recoverable
  through decisions, not knowledge*; (4) exactly ONE action — the drill CTA.
  Loss language appears only inside beat 3, after competence is established.
  Register locked in `MockToMarksReport.headline`, not in the component.
- `COUNTERFACTUAL_ITEM_CAP = 3` (literal, tested — the cohort-cap
  precedent): top 3 costliest decisions; the rest roll up into one collapsed
  line.
- The results summary is the page's ONE focal card; the counterfactual is
  plain text under a hairline (the ProblemStatementBlock pattern); the CTA
  is a full-width button, not a card. **No receipt border** — leftOnTable is
  derived analysis, not a verification receipt.
- Student register, always: "At your accuracy on this topic, skipping this
  question type gains you about 2 marks per mock." Marks, not EV; sentences,
  not formulas; break-even p stays server-side. Negative marks rendered with
  the sign explained ("−⅔ of a mark").
- 17px floor: per-question cost lines are stacked rows (17px label / 15px
  supporting), never a 13px table.
- State matrix: `leftOnTable = 0` → the best screen in the product ("you
  extracted everything you knew" — the success state gets real copy);
  mostly-skipped mock (knewIt ≈ earned) → coaching inverts to "attempt
  more," never naive skip-praise; no careless tags available (MCQ-only) →
  the section renders the headline only, no fabricated decomposition;
  revisiting an old mock → same screen from persisted analysis.
- Reachable, ignorable, repeatable: below the score, scroll-discoverable,
  never blocking.

**W3.2 attempt/skip drill:**
- "Attempt" and "Skip" are equal-weight, equal-size, 44px buttons — neither
  styled primary. The UI must not teach "skipping is giving up" while the
  content teaches the opposite.
- A correct skip gets the **green** confirmation (green = correctness — the
  most persuasive pixel this feature ships).
- Fewer than 5 eligible marked items → honest 422 refusal (quiz-pool
  pattern); DB-less → the readiness routes' "building your baseline" honesty.

**W2.5 decision_tree widget:**
- Interaction model: a **sequential question wizard** extending
  `GuidedWalkthrough`'s skeleton (one question card per view, full-width
  44px choice buttons, breadcrumb of choices) — never a rendered tree
  diagram on a 375px screen.
- Grading: **graded at the leaf only**, ungraded mid-tree; a wrong branch is
  walkable to its dead end before the reveal — the dead end IS the lesson.
  Green marks the correct leaf; this widget is the sanctioned exception to
  the other three kinds' never-judge stance, and the spec says so.
- "Wrong" has no color in Clarity: wrong-leaf treatment is neutral tokens +
  words ("Not the best route here — here's why"), no red anywhere, no
  hard-coded hex. Reason codes render as 17px sentences, never codes.

**W3.7 confidence chip (gated):** one-tap, below the answer input,
neutral tokens (not indigo — it isn't AI; not green — it isn't correctness),
44px (standalone tap; the chip-in-row exemption does not apply), skippable
by simply answering. Close the loop per-attempt: a post-answer echo
("Unsure + correct — trust yourself more") — feedback, not a stored profile,
threading the surveillance invariants. Without the echo, capture decays to
selection-biased zero.

**W3.8 stubs (gated, specified now while intent is fresh):** a deferral is a
plain-text row under a "Deliberately parked" hairline section with its
reason — tokens only, no card, no count-shaming. Re-entry opens on
competence framing (`knewIt`-style recap), never on decay framing, and never
renders the absence gap as a number.
