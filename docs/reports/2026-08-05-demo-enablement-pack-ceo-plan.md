# Demo Enablement Pack — CEO Plan (2026-08-05)

## What this is

A structured plan for removing the remaining friction from the 3-minute moat demo.
Generated by running the full CEO + design + eng + DX review pipeline against the
current codebase state (post v4.26.0, multi-provider LLM support shipped).

## Current state of the demo flow

The moat demo script (`docs/moat-demo.md`) proves personalization is real by showing
the same atom side-by-side for a personalized student (Priya) vs a generic prompt.
The path is:

```
CLI: npm run demo:scenario priya-cbse-12-anxious limits-jee --atoms 5
CLI: npm run demo:scenario arjun-iit-driven limits-jee --atoms 5
Browser: /admin/scenarios → click run → Show neutral version
Browser: /admin/content-rd → Effectiveness Ledger
```

## CEO findings

### F1 — Demo has a CLI dependency (blocks non-technical demos) [CRITICAL]

The first two steps require a terminal. An investor demo where the presenter types
`npx tsx` mid-presentation breaks the narrative. The admin UI shows an empty scenarios
page with no affordance to proceed without CLI.

**Fix:** Add `POST /api/admin/scenarios/demo/seed` + "Seed the moat demo" button in
`/admin/scenarios` empty state. One click → both personas seeded → page auto-refreshes
with two trial rows ready. DB-graceful: seeds the student_model if DATABASE_URL is
present; runs the policy trial either way (trial output is disk-only).

**Concept mapping:** The moat-demo.md references `limits-jee` but that concept is not
present in the repo's modules/ directory. The seed endpoint uses `derivatives-basic`
(present in `modules/project-vidhya-content/concepts/`) which has 8 atoms — enough for
a compelling demo. Update the runbook to reflect this.

### F2 — Design deferred items from 2026-08-03 audit [HIGH]

The design audit deferred six categories. Two are high-risk for a live demo:

- **Indigo semantic violation** — indigo is reserved for AI/tutor/study-plan only but
  appears on non-AI surfaces. This is visible in the demo path (/admin/journey uses
  indigo liberally, which is correct; other pages may drift). Audit the demo-path pages
  specifically.
- **Type-scale violations** — student-facing text below 17px body floor. The demo
  touches LessonPage and ScenariosPage — both must be at spec.

**Fix:** Targeted audit of demo-path pages only (not all 67 pages). Fix violations on
`ScenariosPage.tsx` and any empty-state text introduced by F1's fix.

### F3 — Scenario empty state is a blank wall [HIGH]

When `/admin/scenarios` is empty (which it always is on a fresh deploy), there is no
guidance — just the page header and nothing else. An investor who navigates there before
the operator has run the CLI sees nothing.

Fixed as part of F1: the empty state becomes the demo seed CTA.

### F4 — moat-demo.md references missing concept [MEDIUM]

`limits-jee` does not exist in the local modules/ directory. The runbook's
`npm run demo:scenario priya-cbse-12-anxious limits-jee` would fail on a fresh clone.

**Fix:** Update runbook to use `derivatives-basic` (present in repo). Add note that the
browser-based seed uses this concept automatically.

## Required gates (per step, must pass before merge)

| Gate | Command | Must be |
|---|---|---|
| G1 — TypeScript | `npx tsc --noEmit` | zero errors |
| G2 — Frontend tests | `cd frontend && npm test` | all passing (≥230) |
| G3 — Backend type check | runs inside G1 | covered |
| G4 — Surveillance invariants | included in G2 | covered by the invariant test file |

G1 and G2 are the merge blockers. G4 is automatically covered because
`src/personalization/__tests__/surveillance-invariants.test.ts` is part of the test suite
and any new endpoint that echoes scorer internals would fail it.

## Implementation order

1. **Backend:** `POST /api/admin/scenarios/demo/seed` in `admin-scenarios-routes.ts`
2. **Frontend API:** `seedDemo()` in `frontend/src/api/admin/scenarios.ts`
3. **Frontend page:** empty-state CTA in `ScenariosPage.tsx`
4. **Docs:** update `docs/moat-demo.md` to note the browser option + fix concept ref
5. **Gate:** run G1 + G2, fix anything that breaks, then commit

## What is deferred

- **Indigo sweep across all 67 pages** — too wide for this pack; the demo path only
  needs the new ScenariosPage additions to be compliant.
- **Effectiveness ledger demo data** — the moat demo's closing line references the ledger
  but it requires experiment data that only builds up with real usage. Seeding synthetic
  experiments is out of scope here; the talking point stands as "this is where the loop
  closes" even with an empty ledger.
- **limits-jee concept content** — the concept exists in the JEE curriculum stub but has
  no atoms authored. Authoring it is content work, not platform work.
