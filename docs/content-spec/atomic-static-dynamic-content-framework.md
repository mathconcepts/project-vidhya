# Static-Core and Dynamic-Personalization Content Framework

**Coverage:** 116 atomic GATE Engineering Mathematics topics  
**Status:** research-first content framework; not a substitute for topic-specific source verification

> Every learner receives the same minimum verified learning contract for an atomic topic. Personalization changes the route, representation, scaffold, pacing, examples and assessment delta only when learner evidence, prerequisite diagnosis, constraints or verified source updates justify it.

## Universal mandatory static core

| Anchor | Mandatory content | Why it is non-negotiable |
|---|---|---|
| Scope | Paper/year applicability, notation and out-of-scope boundary. | Prevents teaching the wrong contract. |
| Hook | A short topic-appropriate relevance or prediction prompt. | Earns a learning action without relying on empty engagement. |
| Representation | One concrete, visual, symbolic, numerical, geometric, tabular or algorithmic view. | Gives working memory an object to attach to the formal rule. |
| Formal anchor | Definition/theorem/algorithm and conditions. | Protects mathematical precision. |
| Method selector | When to use the method and one tempting non-method. | Addresses method-selection failure. |
| Worked example | One fully checked example with intermediate states. | Scaffolds novice execution. |
| Boundary | Counterexample, edge case or misconception contrast. | Prevents overgeneralization. |
| Retrieval | Recognition, cued recall and free recall opportunity. | Builds retrieval routes; exact effect must be monitored. |
| Assessment bridge | Relevant MCQ/MSQ/NAT/timed/descriptive behavior. | Transfers concept knowledge to the exam contract. |
| Delayed transfer | Changed-surface follow-up after a delay. | Separates immediate familiarity from durable use. |
| Accessibility | Caption, plain-language and text-only equivalent. | Keeps the same objective reachable through different access routes. |

## Dynamic layer contract

The dynamic layer never regenerates the entire lesson by default. It attaches the smallest delta to a stable anchor. The eligible delta is selected from response accuracy, error code, latency, hint use, confidence, prerequisite probe, assessment mode, time/deadline constraints, uploaded source or source-freshness event. The system records why the delta was attached and what changed.

## Research and quality boundary

The per-topic records are content contracts. Before a topic is promoted to an authoritative lesson, the research pipeline must resolve official scope, inspect topic-specific definitions and conditions, register claims and sources, validate the prerequisite path, code historical evidence with an explicit label, check all mathematics and answer keys, and run retrieval, transfer, accessibility and assessment gates. Claims about frequency, weightage, learner prevalence or hook superiority require appropriate datasets or bounded experiments; they are not inferred from the template.
