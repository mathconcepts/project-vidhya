## 0. The question, made precise

The ask: for **T3 content**, can the Wolfram **local/cloud MCP** connection be
used; can the **Wolfram Demonstrations** corpus, via MCP, become a source of
customised content; and what is the right strategy given Wolfram is a quality
standard.

**"T3" disambiguated (repo audit).** Four tier vocabularies exist; two matter here
and both put Wolfram at tier 3 by convention:
- `src/verification/tiered-orchestrator.ts` — answer-verification **Tier 3 =
  Wolfram|Alpha arbitration** (tier slot structurally locked: `registerVerifier()`
  refuses tiers <4).
- `src/content/resolver.ts:297` — the content resolver's own `tier3()` =
  "Wolfram MCP verification for high-stakes", calling the same
  `verifyProblemWithWolfram`.

So "T3 content" = **content whose mathematical truth is anchored by Wolfram** —
the verification tier and everything content-side that could inherit its
guarantee. That is the scope of this strategy.

## 2. Premises (final gate confirms)

1. **Wolfram's right role is authoring-time and verification-time, never
   student-facing runtime.** Three independent lines converge: the Cloud's
   documented reliability record, the repo's own locked "dependency-free
   interactive kinds" design goal, and the NC license on the one corpus worth
   embedding. A student page must never wait on Wolfram.
2. **The standard is already encoded — the switch is off.** `cas-checker.ts`
   makes Wolfram the ground truth; the gate ledger already carries
   `wolfram_verified` evidence; the whole Tier-3 stack waits on one env var
   plus a licensing check. The strategy's first move is activation, not
   construction.
3. **Demonstrations are a design standard to re-implement, not a content
   library to import.** NC + dead CDF close the import path; the ideas
   (parameter-driven visual intuition, one concept per demo) map 1:1 onto
   Vidhya's existing widget kinds. Independent re-implementation is the
   legally-clean, architecture-clean path (legal review flagged).
4. **MCP is an authoring instrument, not pipeline plumbing.** The session's
   Wolfram MCP (once authorized) gives content-authoring sessions live CAS
   evaluation and plot prototyping. Wiring MCP into the generation pipeline
   itself would duplicate what Tier 1–3 verification already does post-hoc,
   cheaper, on cached content.
5. **No licensing number in this plan is settled.** Commercial API $/call, LLM
   Kit price, Engine production license, Show Steps redistribution — all
   proxy-blocked this session. Every cost-bearing item below is gated on the
   operator pulling real terms from the developer portal. Free-tier use is
   non-commercial: fine for the pre-revenue pilot, revisit at monetization.

## 3. The strategy — four moves, two rejections

### W1 — Turn the standard on (operator, ~15 minutes, no code)
1. Authorize the **Wolfram MCP connector** for Claude sessions (claude.ai
   Settings → Connectors → Wolfram). Unlocks W3's authoring loop.
2. Get a **Wolfram|Alpha AppID** (free tier, non-commercial — pilot-appropriate)
   and set `WOLFRAM_APP_ID` on the Render service. Tier 3 verification, the
   gate-ledger `wolfram_verified` evidence, `wolfram-verify-job`, and the
   pilot's `wolframCheck` leg all go live — zero new code, budget already
   capped at 50 calls/day in the orchestrator.
3. Pull the four unresolved license/price facts from the developer portal;
   record them in the ops runbook (they gate W4 and any monetized use).

### W2 — Make Wolfram provenance structural (code, small)
1. **Provenance honesty:** `evidence_level` + `verification_method` already
   exist; add the convention (validated in `check-practice-items.ts`) that a
   Wolfram-confirmed key records `verification_method` containing
   `+wolfram` (e.g. `hand_solved+wolfram`) with a `verified_at`. Backfill only
   what a session actually re-verifies (W3) — never retro-stamp the release-notes
   claim on the 123 LA items.
2. **Repo hygiene:** fix `/verify-sweep`'s honesty — repoint the skill doc at
   the real `wolfram-verify-job` (and its env caps) instead of the
   nonexistent operation file and phantom tables; or implement the missing
   operation on top of the job. Small, prevents the next session from
   trusting a phantom.
3. **Review-queue surfacing check:** confirm the queue row renders the
   `mathematics` gate's Wolfram evidence string prominently (it exists in
   data; verify the UI shows it — that evidence is what makes operator
   approval fast).

### W3 — Wolfram-assisted authoring loop via MCP (the "customised content" answer)
The concrete answer to "can MCP create customised content": **yes — as the
authoring copilot, producing Vidhya-native artifacts.** In an MCP-authorized
session, per batch of items/concepts, Sonnet agents use `WolframLanguageEvaluator` to:
1. **CAS-check every answer key** before it enters the bank (`Solve`,
   `Integrate`, `Eigenvalues`, numeric evaluation to the contract's
   tolerance) — recorded per W2's provenance convention. This is the pilot's
   spot-check labor, mechanized: the operator approves evidence instead of
   re-deriving by hand — directly attacks the measured minutes-per-item.
2. **Prototype visual intuition** (`Plot`/`ParametricPlot` sanity views), then
   emit the *Vidhya-native* artifact: `gif-scene` JSON (`x_expr`/`y_expr` in
   the existing grammar) or `manipulable`/`simulation` specs — via a small
   **WL→safe-evaluator translation adapter** (new, ~1 file + tests: maps the
   supported operator/function subset, REFUSES expressions outside it — e.g.
   `Gamma`, `Piecewise` — with a D8-precise message naming the offending head).
3. **Parametrized problem families** with symbolic guarantees (solution
   exists, is unique, is hand-computable) — specs feed the existing batch
   pipeline; Wolfram guarantees at authoring time, the cascade still verifies
   at generation time.

Deliverables: `docs/ops/wolfram-authoring-runbook.md` + the translation
adapter + a worked example batch (one LA concept end-to-end). No student-path
change at all.

### W4 — Demonstrations as the visual standard (data + authoring, gated on legal note)
Per top-leverage concept (the corpus's leverage list): a curated mapping
`concept → Demonstrations idea → Vidhya widget spec`, committed as data
(`data/curriculum/gate-em/visual-standards.yml`): the demo's *idea* named and
linked (MIT preview snapshot allowed for authoring reference), the
independent re-implementation speced as `manipulable`/`simulation`/branching
`guided_walkthrough`/gif-scene. First wave: the eigen cluster + VC theorem
geometry (where 3Blue1Brown/Wolfram-grade intuition pays most).
**Gate:** a one-paragraph legal note in the file header stating the
independent-re-implementation basis, flagged `design_hypothesis` until the
operator gets a real legal read.

### Rejected (explicit, with reasons)
- **R1 — Embedding Wolfram Cloud interactives student-facing.** Live uptime
  dependency against a documented outage history; violates the repo's locked
  dependency-free widget rule; 60-day free-tier expiry would rot pages
  silently. Revisit only as an explicitly-labeled optional enrichment, never
  the primary interactive.
- **R2 — Importing/embedding Demonstrations content.** CC BY-NC-SA blocks
  commercial redistribution; CDF is dead anyway. The MIT preview-snapshot
  carve-out is for authoring reference only.
- **Deferred — Show Steps content in worked examples** (redistribution terms
  unconfirmed → W1.3 must answer first); **Wolfram Engine batch asset
  generation** (needs a production license + a reason `gifenc` can't cover;
  none today); **MCP inside the generation pipeline** (duplicates the
  cascade).

## 5. Failure modes

| Path | Failure | Handling |
|---|---|---|
| Tier 3 live, key invalid/quota hit | cascade falls back (already: confidence-penalized LLM verdict), never blocks | existing, tested |
| MCP session eval disagrees with committed key | item flagged, goes to review queue with both values — never silently rewritten (writer guard D5 already refuses) | W3.1 |
| WL expression outside widget grammar | translation adapter refuses, names the offending function — author picks a different form | W3.2 |
| Free-tier NC limit vs monetization | W1.3's recorded terms gate the switch to paid API before any revenue traffic | plan-level |
| Demonstrations legal read comes back negative | W4 mappings keep the concept→idea table (facts aren't copyrightable) and drop preview links; specs unaffected (independent code) | W4 gate |
| Wolfram Cloud MCP outage mid-authoring | authoring session degrades to hand-verification (the status quo); nothing student-facing moves | by design |
